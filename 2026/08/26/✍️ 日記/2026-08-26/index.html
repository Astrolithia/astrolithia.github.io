配置 DNS

容器的 DNS 机制

Docker 容器的 DNS 配置有两种情况：

  1. 默认 Bridge 网络：继承宿主机的 DNS 配置
  2. 自定义网络（推荐）：使用 Docker 嵌入式 DNS 服务器，支持通过 容器名 进行服务发现
    如果希望所有容器都使用特定的 DNS 服务器（而不是继承宿主机），可以修改 /etc/docker/daemon.json

修改后需要重启 docker 服务

网络类型

网络类型 适用场景
Bridge 大多数单机场景
Host 需要最高网络性能时
None 完全隔离的容器
Overlay Docker Swarm 集群
Macvlan Linux 主机上需要直接接入物理网络
Ipvlan 同网段大量容器、对 MAC 数量受限的网络

想做一个提供 App 端 网页端的陪伴功能的 agent 可以导入模型

--force-recreate 的典型场景

  • 容器内部被手动修改过
  • 容器运行状态异常
  • 使用了相同镜像标签，但镜像内容被替换

最佳实践与安全

  1. 限制监听 IP
    默认情况下，-p 8080:80 会监听所有可用地址，常见输出包括 0.0.0.0:8080 和 [::8080]。这意味着任何人只要能连接你的宿主机 IP，就能访问服务
    如果不希望对外暴露，应绑定到回环地址
  2. 避免端口冲突
    如果宿主机 8080 已经被占用了，容器将无法启动
    解决方案：更换宿主机端口 -p 8081:80、让 Docker 自动分配 -p 80
