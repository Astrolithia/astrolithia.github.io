一句话理解 Docker

轻量级的虚拟化技术，让应用程序及其依赖环境可以被打包成一个标准化的单元，在满足架构、内核能力和外部环境前提的环境中高度一致地运行

Docker vs 虚拟机

传统虚拟机

虚拟出一套完整的硬件，在其上运行一个完整的操作系统，再在该系统上运行应用

Docker 容器

Docker 容器内的应用直接运行于宿主的内核，容器内没有自己的内核，也没有进行硬件虚拟

为什么要用 Docker

核心理念：一次构建，到处运行
秒级启动、
Docker 完美契合 DevOps 的工作流程

Docker 是微服务架构的基石
Docker 让你可以

  • 隔离服务：每个服务运行在独立容器中，互不干扰
  • 独立扩展：哪个服务负载高，就单独扩展哪个
  • 独立部署：更新一个服务不影响其他服务
  • 技术多样：不同服务可以用不同语言和框架

Docker 不适合的环境

  1. 需要完全隔离的场景：容器共享宿主机内核，隔离型不如虚拟机。如果需要运行不受信任的代码，虚拟机可能更安全
  2. 需要特殊内核的场景：容器使用宿主机内核
  3. Windows 原生应用：虽然 Docker 支持 Windows 容器，但生态不如 Linux 容器成熟
  4. 桌面应用：Docker 主要面向服务端应用。桌面 GUI 应用的容器化虽然可行，但通常得不偿失

基本概念

Docker 镜像作为容器运行的基石，其设计理念和实现机制至关重要。

Docker 镜像

Docker 镜像是一个只读的模版，包含了运行应用所需的一切：代码、运行时、库、环境变量和配置文件
操作系统分为内核和用户空间
Docker 镜像包含

  • 程序文件
  • 库文件
  • 配置文件
  • 环境变量
  • 元数据
    镜像是只读的 镜像不包含动态数据 构建后内容不会改变
    镜像的分层存储机制是 Docker 最具创新性的特性之一，通过 Union FS 技术，Docker 能够高效地构建和管理镜像

容器

容器是镜像的运行实例，如果把镜像比作程序，那么容器就是进程。用面向对象编程的术语来说：镜像是类（Class），容器是对象（Instance）

容器的本质

容器的本质是一个特殊的进程。
普通进程的进程与进程之间共享系统资源，共享网络，共享文件系统
容器进程每个进程之间是独立进程空间，独立网络环境，独立文件系统，独立用户空间的

容器存储层的生命周期

容器存储层与容器生命周期绑定。容器删除，数据就没了

正确的数据持久化方式

按照 Docker 最佳实践，容器存储层应该保持 无状态。需要持久化的数据应该使用：

  • 数据卷（Volume）：Docker 管理的存储
    适用场景：数据库、应用数据
  • 绑定挂载（Bind Mount）：挂载宿主机目录
    适用场景：开发时共享代码

容器的生命周期

容器与进程的关系

容器的生命周期=主进程（PID 1）的生命周期
主进程运行，容器运行；主进程退出，容器停止
这就是为什么：

官方 nginx 镜像默认使用 nginx -g 'daemon off;'，让主进程保持在前台运行，这样容器才会持续处于运行状态

Registry

镜像构建完成后，可以在当前机器上运行，但如果需要在其他服务器上使用这个镜像，就需要一个集中的存储和分发服务──这就是 Docker Registry。

Docker Registry 中可以包含多个 Repository（仓库），每个 Repository 可以包含多个 Tag
![[Pasted image 20260821144053.png]]
一个镜像的完整名称由 Registry 地址、用户名/组织名、仓库名和标签组成

[registry 地址/][用户名/]仓库名[:标签]

如果不指定 Registry 地址，默认使用 Docker Hub。如果不指定标签，默认使用 latest。
