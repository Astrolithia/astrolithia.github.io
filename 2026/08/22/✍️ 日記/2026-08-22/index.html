镜像构建上下文

docker build 默认会通过 Buildx 向 BuildKit 后端发起构建请求；无论后端运行在本地还是远端，位置参数指定的都是 构建上下文
将本地文件复制进镜像：COPY、ADD，它能访问的范围正是传给 docker build 的那个上下文
如果上下文是本地目录，那么这个目录中的文件和子目录就会成为可用输入；如果上下文是远端 Git 仓库或 tar 包，那么构建器会直接获取对应内容。对于本地目录，BuildKit 会按需读取构建过程中真正需要的文件，而不是让 Dockerfile 任意访问宿主机上的任意路径
如果在 Dockerfile 中这么写：

这并不是要复制执行 docker build 命令所在目录下的 package.json，也不是复制 Dockerfile 所在目录下的 package.json，而是复制 上下文目录下的 package.json
把上下文切到硬盘根目录去构建镜像可能会导致上下文变得过大，导致构建缓慢甚至失败
如果不希望一些文件在构建时传给 Docker 引擎，可以用 .dockerignore

docker build 支持从 URL 构建，可以直接从远端 Git 仓库作为上下文

这行命令标识：把 Git 仓库作为构建上下文，使用 mybranch 分支中的 docker/ 子目录来构建

如果给的 URL 不是一个 Git repo，而是一个 tar 压缩包，那么 Docker 引擎会下载这个包，并自动解压缩，以其作为上下文，开始构建
